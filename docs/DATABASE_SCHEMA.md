# Database schema

Prisma schema: `apps/api/prisma/schema.prisma`. Migrations: `apps/api/prisma/migrations/20261102100000_init`, `20261102120000_task_schedule`, `20261102130000_focus_pause`, `20261102140000_website_rules`, `20261102150000_habits_goals`, `20261102160000_account_preferences`, and `20261102170000_task_recurrence`. Provider: PostgreSQL. IDs are UUIDs generated by Prisma on insert (`@default(uuid())`), not a database default.

Every product row that belongs to a person has `userId` and a foreign key to `users` with `ON DELETE CASCADE`, except where a parent row uses `ON DELETE SET NULL` (task category, focus session task).

## Used by the shipped API

- `users` — email unique, password hash, name
- `sessions` — token hash unique, expiry, optional user agent. Not in the original entity list; required for server sessions
- `user_preferences` — timezone, theme (`light`, `dark`, or `system`), week start, `focus_default_seconds` (default 1500), and `language` (default `en`, stored only). One row per user
- `tasks` — title, description, status, priority, `is_urgent`, `is_important`, deadline, `scheduled_start`, `scheduled_end`, completed_at, `recurrence` (`NONE`, `DAILY`, or `WEEKLY`, default `NONE`), optional `recurred_from_id`, optional category. The schedule columns are nullable. Both null means the task has no time block. `recurred_from_id` is unique and points at the completed task this row was created from
- `categories` — name and optional color, unique per user and name. Deleting a category sets `tasks.category_id` null
- `tags` — name, unique per user and name
- `task_tags` — task, tag, and the session user. Primary key is `(task_id, tag_id)`
- `subtasks` — title, completed, position, and the owning user
- `focus_sessions` — planned seconds, optional task, `started_at`, `ended_at`, `paused_at`, `paused_seconds`, and `completed`. `elapsed_seconds` is unused. An active session has a null `ended_at`
- `website_rules` — domain, `BLOCK` or `ALLOW` (`LIMIT` remains in the enum), enabled, optional daily limit, optional schedule minutes
- `website_usage` — seconds per rule per date
- `website_usage_events` — one row per client event id. The pair `(user_id, client_event_id)` is unique
- `habits` — name, `DAILY` or `WEEKLY`, and `target_count`
- `habit_entries` — one row per habit and `entry_date`, with `count`. Unique on `(habit_id, entry_date)`
- `goals` — title, description, status, and `target_date` (the deadline). No progress column
- `milestones` — title, completed, `position`
- `goal_tasks` — goal, task, and the session user. Primary key is `(goal_id, task_id)`

There is no quadrant column and no goal progress column. `20261102120000_task_schedule` adds the two schedule columns and an index on `(user_id, scheduled_start)`. `20261102130000_focus_pause` adds the pause columns, an index on `(user_id, ended_at)`, and a partial unique index so only one row per user can have `ended_at` null. `20261102140000_website_rules` adds `ALLOW`, the schedule minutes, and `website_usage_events`. `20261102150000_habits_goals` adds `target_count`, habit entry `count`, milestone `position`, and `goal_tasks`. `20261102160000_account_preferences` adds `focus_default_seconds` and `language`. `20261102170000_task_recurrence` adds `recurrence` and unique `recurred_from_id`. None of those migrations were applied here. `language` is not a translation catalog.

## Declared for later phases

`task_time_logs`, `notifications`.

Indexes cover owner plus status, deadline, scheduled start, priority, and created time on tasks, plus owner indexes on the other tables. Tags and categories are unique per user and name. Website rules are unique per user and domain.

Apply with `npm exec -w @focusflow/api -- prisma migrate deploy` after Postgres is up. That command was not run here because Postgres was not available.
